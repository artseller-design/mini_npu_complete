# Mini NPU Simulator — 실행 및 결과 리포트

## 1. 프로젝트 개요
Python 3.8 이상의 표준 라이브러리(`json`, `math`, `re`, `time`, `pathlib`)만 사용하여 MAC(Multiply-Accumulate)을 이중 반복문으로 계산하는 패턴 판별 시뮬레이터입니다. 이 프로그램은 실제 NPU 하드웨어를 구현한 것이 아니라, NPU가 많이 사용하는 MAC 계산의 기초 원리를 CPU에서 모사합니다.

## 2. 파일 구조

```text
mini_npu/
├── main.py       # 3×3 입력, JSON 일괄 분석, MAC 연산, 성능 측정
├── data.json     # 업로드된 5×5, 13×13, 25×25 필터와 6개 패턴
└── README.md     # 실행 방법 및 결과 리포트
```

## 3. 실행 방법 (Windows PowerShell)

1. 파일 3개를 동일한 폴더에 둡니다. 제공받은 `data(1).json` 파일은 **`data.json`으로 이름을 바꿔야** 합니다.
2. VS Code에서 **파일 → 폴더 열기**로 이 폴더를 엽니다.
3. 터미널 → 새 터미널을 선택하고 다음을 실행합니다.

```powershell
python main.py
```

`python`이 인식되지 않을 때에는 `py main.py`를 실행합니다.

- `1`: 사용자 입력 3×3 모드 (직접 입력 또는 패턴 자동 생성 선택)
- `2`: `data.json` 분석 모드 (6개 패턴의 판정 및 PASS/FAIL, 성능 분석)
- `3`: 홀수 크기 Cross/X 패턴 생성기 (보너스 기능)

### 모드 1 검증 입력

필터 A (십자가):

```text
0 1 0
1 1 1
0 1 0
```

필터 B (X):

```text
1 0 1
0 1 0
1 0 1
```

패턴 (X):

```text
1 0 1
0 1 0
1 0 1
```

**검증 결과:** A 점수 `1`, B 점수 `5`, 판정 `B`.

## 4. 구현 요약

1. `validate_matrix()`는 N×N 크기, 숫자 타입, NaN/무한대를 검증합니다.
2. `read_matrix()`는 한 줄에 N개 숫자를 입력받으며 오류가 있으면 같은 행을 다시 요청합니다.
3. `mac()`은 이중 `for` 문을 사용해 `pattern[i][j] * filter[i][j]`를 누적합니다.
4. `normalize_label()`은 필터 키 `cross`→`Cross`, `x`→`X`, 기대값 `+`→`Cross`, `x`→`X`로 표준화합니다.
5. `analyze_case()`는 `size_N_idx`로 크기를 추출해 적절한 `size_N` 필터와 대조합니다.
6. `judge()`는 `abs(score_a - score_b) < 1e-9`이면 `UNDECIDED`를 반환합니다.
7. `run_json_mode()`는 각 케이스의 스키마 오류가 전체 분석을 중단시키지 않도록 개별적으로 FAIL 처리합니다.
8. `measure_average()`는 입력·출력과 파일 읽기를 제외하고 연산 함수 호출 시간만 10회 측정합니다.
9. `performance_report()`는 패턴 크기마다 평균 시간(ms)과 곱셈 횟수 N²를 표시합니다.
10. `generate_pattern()`은 홀수 크기의 Cross/X 패턴을 생성합니다.

## 5. 결과 리포트 — 업로드된 원본 데이터 기준

**검증 환경:** Python 실행으로 `main.py`를 실행하고 함께 받은 `data(1).json`을 `data.json`으로 복사하여 분석함.

| 케이스 | Cross 점수 | X 점수 | 판정 | 기대값 | 결과 |
| --- | ---: | ---: | --- | --- | --- |
| `size_5_1` | 0.9 | 0.8999999999999999 | UNDECIDED | X | FAIL |
| `size_5_2` | 8.9 | 0.1 | Cross | Cross | PASS |
| `size_13_1` | 0.3 | 14.70000000000001 | X | X | PASS |
| `size_13_2` | 7.499999999999997 | 7.5 | UNDECIDED | Cross | FAIL |
| `size_25_1` | 4.9 | 4.899999999999999 | UNDECIDED | X | FAIL |
| `size_25_2` | 52.9 | 0.1 | Cross | Cross | PASS |

**총 6개 / PASS 3개 / FAIL 3개.** 세 FAIL은 스키마 누락이나 코드 예외가 아니라, 두 점수의 차이가 epsilon보다 작을 때 `UNDECIDED`로 처리하는 **정상적인 정책 결과**입니다.

### 5.1 실패 원인 분석 — 10줄 이상

1. `size_5_1`의 Cross 점수는 `0.9`, X 점수는 `0.8999999999999999`입니다.
2. 두 점수의 차이는 약 `1.11×10⁻¹⁶`으로 `epsilon=1×10⁻⁹`보다 작습니다.
3. 따라서 `size_5_1`은 기대값 `X`와 관계없이 `UNDECIDED`로 판정되어 FAIL입니다.
4. `size_13_2`의 Cross 점수는 `7.499999999999997`, X 점수는 `7.5`입니다.
5. 두 점수 차이는 약 `2.66×10⁻¹⁵`이므로 동점으로 판정됩니다.
6. 따라서 `size_13_2`는 기대값 `Cross`와 달라 FAIL입니다.
7. `size_25_1`의 Cross 점수는 `4.9`, X 점수는 `4.899999999999999`입니다.
8. 두 점수 차이는 약 `1.78×10⁻¹⁵`이므로 동점으로 판정됩니다.
9. 따라서 `size_25_1`은 기대값 `X`와 달라 FAIL입니다.
10. 이러한 차이는 소수를 이진 부동소수점 수로 저장하고 합산할 때 발생할 수 있습니다.
11. 작은 오차만으로 Cross 또는 X의 승자를 결정하면 반복 연산이나 환경 차이로 결과가 흔들릴 수 있습니다.
12. 이를 방지하기 위해 두 점수 차이가 epsilon 미만일 때 `UNDECIDED`를 반환하도록 설계했습니다.
13. 점수가 동점인 케이스를 억지로 PASS 처리하면 과제의 동점 정책을 위반하므로, FAIL과 사유를 유지합니다.
14. `expected` 값 `+`와 `x`는 비교 전에 각각 `Cross`, `X`로 정규화되어 정상 비교됩니다.
15. 필터의 `cross`, `x` 키도 같은 표준 라벨로 처리되어 키 표기 차이에 따른 잘못된 FAIL을 방지합니다.
16. 행 또는 열 개수가 N과 다르면 `validate_matrix()`에서 스키마 오류로 판정하고 해당 케이스만 FAIL 처리합니다.
17. 문자가 섞인 행렬 값이나 NaN·무한대 역시 데이터 오류로 구분하고 연산을 중단합니다.
18. 즉, 문제의 원인은 **데이터·스키마**, **로직**, **수치 비교 정책**으로 나누어 진단할 수 있습니다.
19. 이번 원본 파일의 세 실패는 모두 세 번째 범주인 **수치 비교 정책에 따른 동점 처리**에 해당합니다.
20. 이 결과는 알고리즘이 실패했다는 뜻이 아니라, 제출 기준에 맞게 예측 불가 사례를 식별했다는 뜻입니다.

### 5.2 성능 분석 — MAC 1회 호출, 10회 평균

아래 수치는 한 번의 검증 환경에서 측정한 값으로, 컴퓨터나 실행 시점에 따라 달라질 수 있습니다.

| 행렬 크기 | 평균 연산 시간 (ms) | 곱셈·누적 위치 수 N² |
| --- | ---: | ---: |
| 3×3 | 0.000810 | 9 |
| 5×5 | 0.001306 | 25 |
| 13×13 | 0.006998 | 169 |
| 25×25 | 0.025865 | 625 |

- N행의 각 행에서 N열을 모두 순회하므로 MAC 하나의 연산 횟수는 정확히 **N²**개입니다.
- N이 5→25로 5배가 되면 행렬 원소 수는 25→625로 25배가 됩니다.
- 따라서 이중 반복문으로 구현한 MAC 함수의 **시간 복잡도는 O(N²)**입니다.
- 두 필터를 평가하면 MAC을 두 번 실행하지만, 상수배는 빅오 표기에서 제외되어 여전히 O(N²)입니다.
- 실제 측정 시간은 작은 수치라 운영체제 스케줄링, CPU 상태, Python 인터프리터 부하에 영향을 받습니다.
- 본 프로그램은 NPU의 병렬 처리 성능을 직접 측정하지 않으며, 단일 CPU 코드에서 MAC 연산 크기별 실행 시간을 비교합니다.

## 6. 재현성 및 오류 처리 검증

- 직접 입력 모드에서 제시한 3×3 필터와 X 패턴 입력 시 `A=1`, `B=5`, `판정=B`가 출력됨을 검증했습니다.
- 3×3 입력에서 숫자를 두 개만 입력하면 오류 문구를 표시한 뒤 같은 행을 재입력하도록 동작함을 검증했습니다.
- 업로드된 원본 JSON 분석 시 `총 6 / 통과 3 / 실패 3`을 확인했습니다.
- 원본 JSON에서 필터 키 `cross`, `x` 및 기대 라벨 `+`, `x`를 정상적으로 표준화했습니다.
- JSON의 행렬 크기/값 오류는 케이스별 `FAIL`로 처리하도록 구현되어 있습니다.
